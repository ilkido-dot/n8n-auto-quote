## What this run shows

- **LLM extraction followed the rules in 10/10 emails.** No invented quantities, no hallucinated items from quoted text, negation handled, 中英混用 handled.
- **All 6 failures are in the deterministic code after the LLM**: it assumes every field is filled and every product is found. A `null` becomes a `$0` quote instead of a stop.
- T07 is the most dangerous: a partial $720 quote that looks complete.

## Bugs found while setting up the test (before v1)

1. Output Parser still had n8n's default example schema (`state` / `cities`) → it validated nothing.
2. Old prompt showed `"數量": 0` as the format example → LLM filled `0` for "do you have X in stock?".
3. Old Code node used `$input.first()` → with 10 emails, 9 would have been silently ignored.

## Fix plan for v2 (step 3)

- Route to human review when: `是新詢價` is false, any `數量` is null, any item not found in price list, total > 100 units.
- If size is null and the variety has exactly one size in the price list, fill it in code (not by the LLM).

## Limits of this result (say this in the README)

- 10 emails written by me, one run each. 10/10 shows the rules work on these cases, not that the system is production-ready.
- LLM output can vary between runs; repeat runs needed before trusting the rate.
- T06 passes via the accepted alternative: typos go to a human instead of being auto-corrected (deliberate: a wrong guess would quote the wrong plant).
